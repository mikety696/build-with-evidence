# 02 · 提示与上下文工程

## 1. 五要素规格（每个任务都按这个结构写）

```
【目标】要达成的用户可见结果（一句话，可测量）
【边界】明确不做什么；改动范围上限（目录/模块）
【现状】相关文件:行号、现有行为、复现命令、错误堆栈
【约束】技术栈/性能预算/安全要求/兼容性/工期；必须遵守的项目约定
【完成定义】跑什么命令、期望什么输出、什么截图算验收通过
```

五要素里 ROI 最高的是**【完成定义】**。它把「开放式生成」变成「有终点的搜索」——AI 有了终止条件，才会自己迭代到通过，而不是给你一版看起来不错的东西。

## 2. 上下文投喂优先级

从高到低，宁缺毋滥：

1. **真实代码**（相关文件的准确路径 + 行号，让 AI 自己读，别粘贴截断版）
2. **可复现命令与真实输出**（比任何形容词都有效）
3. **接口契约**（schema、OpenAPI、类型定义、数据库 DDL）
4. **项目约定**（`AGENTS.md`，一次性常驻）
5. **风格偏好**（最低优先级，通常可以省）

无关文件塞进上下文会**降低**质量：模型会为了「照顾」这些内容做出奇怪权衡。给路径让它按需检索，比全量粘贴好。

## 3. 好/坏提示对照表

| 坏 | 为什么坏 | 好 |
|---|---|---|
| 帮我写个登录 | 假设全由 AI 填 | 实现邮箱+密码登录：bcrypt(cost≥12)、会话走 httpOnly SameSite=Lax cookie、5 次失败锁定 15 分钟、无「用户不存在」差异消息；不实现第三方登录。完成=通过我给的 6 条测试 |
| 这段代码有 bug，修一下 | 无复现、无期望 | 命令 `X` 输入 A 期望 B，实际 C，堆栈附后；先写复现测试再修，贴运行输出 |
| 优化一下性能 | 无边界无基线 | 接口 P95 从 480ms 降到 <120ms。先加计时剖析并给数据，指出前 3 个瓶颈，只做证据支持的改动 |
| 重构这个模块 | 无行为保持约束 | 保持公共 API 与现有测试全绿的前提下拆分职责；每步一提交，不允许改断言 |
| 你确定这样安全吗？ | 事后追问，成本高 | 实现前先做威胁建模：列出入口、信任边界、滥用案例与对应防御 |
| 加个新功能，顺便整理下代码 | 变更集混杂，难评审 | 只做功能；整理另开一个变更集 |
| 按最佳实践来 | 「最佳实践」无定义 | 明确引用哪份规范/内部约定第几条 |
| （直接贴生产密钥和真实用户数据） | 数据外泄 | 贴脱敏样例 + 字段结构说明 |

## 4. 追问句式库（复制即用）

**收敛需求**
- 先别写代码。提出 3–5 个最影响架构的问题，每题给默认建议。
- 列出这个方案依赖的全部隐含假设，按「错了要返工」程度排序。
- 明确写出本任务的 non-goals。

**打开思路**
- 给 3 个方案 + 取舍表（性能/扩展性/安全/成本），推荐一个并说代价。
- 有没有本可复用而不该自己写的东西？（库、平台能力、现有内部模块）
- 如果我完全不做这个功能，最坏会怎样？

**逼出证据**
- 运行 `test + typecheck + lint + build`，把真实输出贴出来，失败就继续修到通过。
- 这个改动可能被破坏的 5 个地方是什么？你如何逐一验证？
- 给出改动前后的性能/体积/复杂度数字对比。
- 哪些分支没被测试覆盖？补上。

**切换视角**
- 以攻击者视角写一段 PoC 打穿刚才的实现，再补防御与回归测试。
- 以「六个月后接手的工程师」审查可读性与缺失文档。
- 以 QA 身份列出 10 个边界/异常用例并跑给我看。

**控制范围**
- 只改 `<目录>`，其他文件需要改动先向我列清单说明理由。
- 停止实现，先给我 diff 计划。
- 不要新增依赖；确实必须则先说明理由与许可证。

## 5. 上下文管理（决定长任务成败）

- **探索交给子智能体**：跨多文件的「找找看」交给只读探索型代理，主对话只接收结论 + 文件:行号。
- **长会话定期压缩**：进入新阶段前，让 AI 输出「当前状态 / 已定决策 / 剩余任务 / 阻塞点」四段小结，作为新基线。
- **一任务一会话**：不相关任务开新会话，避免互相污染。
- **反复解释 = 基线缺失**：同一件事解释第三次，立刻写进 `AGENTS.md` 或知识库。

## 6. 常见反模式

1. 巨型一次性提示（AI 会挑最容易的部分做，把难的悄悄跳过）。
2. 无终止条件的开放式指令（「做得更好一点」→ 无法判断完成，也无法判断失败）。
3. 接受第一个可用答案，不做二次评审。
4. 让 AI 猜你的隐含偏好，而不是把偏好规则化写下来。
5. 用对话长度换确定性——不断追问「你确定吗」不如让它跑一条命令。
